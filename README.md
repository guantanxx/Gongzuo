# 光序 · 商业照明 B 端自媒体工作台

面向商业照明、工程亮化、投影灯 / 水纹灯 / 激光灯 / 文旅灯具的独立内容工作台，服务总包、装修公司、经销商与甲方客户。

**原生 HTML + CSS + JavaScript，零第三方运行依赖，无后端、无数据库、无外部字体、图片、接口或服务。数据全部保存在当前浏览器的 localStorage。** 可直接部署到 GitHub Pages。

## 设计与布局

默认深色：哑光深炭灰、低饱和灰蓝、微光浅蓝。以细线、留白、轻渐变和 CSS 光束表达照明属性，不使用艳色、厚重卡片或弹跳动画；浅色主题可切换并保存。尊重系统“减少动态效果”设置。

桌面左侧导航永久固定并可独立滚动；手机转为顶部固定导航，功能入口横向滚动。导航包含实时全局搜索、**新建灵感**和**导出全部**快捷按钮。

各表单输入实时保留草稿，保存、复制、生成和导出有微光 toast；本地保存状态也显示在桌面顶部。存储写入失败会提示失败，不会将未写入的数据计为成功保存。

保存文案会将关联“待撰写”选题标为“拍摄中”；录入关联视频数据会标为“已发布”。删除灵感或选题不会级联删除已生成内容。切换文案或模板可能替换工作草稿时会确认，历史版本保留。

## 使用

直接打开 `index.html` 即可运行。推荐使用本地 HTTP 服务，以获得稳定的存储与复制行为：

```sh
cd Gongzuo
python3 -m http.server 8000
```

浏览器访问该服务。也可以使用 GitHub Pages 的 HTTPS 页面，无需安装依赖、构建或配置密钥。

推荐流程：设置 IP → 拆解工程向文案 → 记录现场灵感 → 五套选题 → 工程口播与版本 → 拍摄待办 → 视频 / 直播数据复盘。

### 模板占位符

`{{IP}}`、`{{客户}}`、`{{产品}}`、`{{联系}}` 会在复制或载入时替换为设置中的内容；**【方括号】**表示需自行补充的真实资料。内置模板不能直接删除，可“另存为自定义”后修改。

直播开场模板载入左侧开场编辑器，完善主题、目标后生成新策划；不会修改已保存的其他直播。口播和询盘模板载入文案编辑器，可继续编辑、保存版本。

## CSV：Excel 导出与批量回填

**灵感库、选题库、视频复盘和直播记录**顶部都有 CSV 导出 / 导入按钮。导出始终包含当前模块的全部记录；空库可导出表头作为填写模板。

1. 导出 CSV，在 Excel 中打开并修改；新增行可以留空 ID。
2. 另存为 **CSV UTF-8（逗号分隔）**，日期使用 `YYYY-MM-DD`，数量使用非负整数。
3. 在原模块导入，先查看新增 / 更新数量与记录预览，再点“确认导入”。取消不会修改数据。

导出使用 UTF-8 BOM、CRLF 行尾与标准双引号转义，支持中文、逗号、引号和多行正文。公式开头的文本会附加保护前缀，避免表格软件将其当作公式执行；本站再次导入时会还原。建议在 Excel 中把 ID 列设为文本。

### 匹配与校验规则

- 保留已有 **ID** 会更新对应记录；文件只提供部分列时，已有记录未提供的字段保留。
- 没有 ID 时按内容匹配：灵感为标题 + 内容，选题为标题 + 钩子，视频和直播为标题 + 发布 / 计划日期。视频也可按关联选题 ID 匹配。若同时修改这些匹配字段，请务必保留原 ID。
- 选题新行需包含标题、封面文案、5 秒钩子；灵感需标题与内容；视频和直播需标题与日期。
- 标签列导出为 JSON 数组，也接受 `投影灯|工程案例` 或逗号分隔文本。
- 直播 CSV 包含完整脚本、待办 JSON、复盘数据及复盘状态，支持再次导入还原。“已复盘”填写“是 / 否”，询盘等复盘指标可直接在 Excel 修改。
- 列名可使用导出的中文表头或对应英文键名；不接受未知 / 重复表头、错误列数、未闭合引号、无效状态 / 日期 / 数值及冲突记录。
- 一次最多 10 MB / 10000 行。**任一行校验失败，整批都不会写入**。导入是合并更新，不会删除文件中未包含的记录。
- CSV 用于四个业务表的数据交换；整机迁移请使用 JSON，以包含文案版本、拆解、模板、待办与草稿。

## 数据口径与生成边界

- 来源链接仅作为记录；应用不访问抖音等平台，不抓取视频，也不调用远程 AI。拆解依赖粘贴文案，生成采用行业规则与模板，不能保证流量或成交。
- 口播按约 3.5 字 / 秒（不含空白）估算篇幅，实际时长请朗读校准。支持 IP 风格关键词和近期稿件句长的简单规则适配，不训练模型。
- 参数、价格、案例、质保、交期与测试效果必须自行核实。模板不会自动制造真实项目或检测证明。
- 每条视频保存一份最新累计数据，更新用编辑。图表按**视频发布日期**聚合累计表现，不能代表播放发生日的增长曲线。
- 首页“已发布视频”合并已发布选题与独立录入视频，按关联选题去重；“累计询盘”为视频与已复盘直播询盘次数合计，不是去重客户数。
- 待办提醒属于页面内日程提示，不发送浏览器或系统推送通知。

## 备份与存储

数据键沿用 `gongzuo.workspace.v1`，内部结构版本为 2，兼容先前版本 1 的 JSON 和本地数据；“待写 / 制作”会迁移为“待撰写 / 拍摄中”，原有记录和文案版本保留。

右侧栏“导出全部”与设置中的 JSON 导出相同，包含全部业务数据、自定义模板、待办、IP、主题和草稿。恢复前校验并确认覆盖，最大 20 MB；格式错误、取消或写入失败不覆盖原数据。内置模板随代码提供，不计入自定义模板数。

localStorage 只属于当前浏览器当前来源。换设备、浏览器、域名、协议或端口后需手动导入备份；清除站点数据会清空记录。建议定期导出。存储损坏时会暂停写入，可先导出原始内容排查，再恢复有效备份。数据不经过云端同步，也不提供账户隔离或加密。

复制优先使用原生 Clipboard API，浏览器不允许时尝试本地复制后备方式；仍失败会提示手动选择复制，不会误报成功。

网页本身无需 Node。开发时可运行以下无第三方依赖的测试：

```sh
node --test tests/native.test.js
node --check app.js
```

## GitHub Pages 部署

1. 将全部文件推送到 `guantanxx/Gongzuo` 的 `main` 分支，根目录保留 `index.html`。
2. 仓库 **Settings → Pages → Build and deployment** 选择 **Deploy from a branch**。
3. 分支选择 **main**，目录 **/ (root)**，保存。
4. 等待部署成功，访问 Pages 面板显示的网址，通常为 `https://guantanxx.github.io/Gongzuo/`。

全部资源使用相对路径，适配仓库子路径。启用上述设置后，后续 `main` 推送会更新站点；保存本机数据不会自动提交到 GitHub。
