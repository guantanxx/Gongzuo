# 创作舱 · 自媒体工作台

独立静态自媒体工作台，使用 **HTML + CSS + 原生 JavaScript**，不加载任何第三方框架、库、字体、接口或服务。不依赖后端和数据库，所有数据存储于浏览器 `localStorage`，可部署到 GitHub Pages。

## 功能

| 模块 | 已支持的操作 |
| --- | --- |
| 爆款拆解 | 记录抖音 HTTPS 链接、粘贴原文；分析开头钩子、受众、结构、矛盾与亮点，生成创作建议；报告保存、查看、删除 |
| 灵感库 | 新增、编辑、删除、全文检索、标签去重与筛选；一键衍生选题 |
| 选题库 | 选择灵感生成五套标题、封面标题及 5 秒开头；按状态筛选、删除、一键写文案；待写 / 制作 / 已发布状态管理 |
| 文案生成 | 输入或选用选题、补充素材，按 10–600 秒生成口播稿；编辑草稿自动保存；保存多个历史版本、载入版本继续编辑、删除文案 |
| 直播中心 | 创建主题、日期、时长、目标和素材；生成可编辑的分段脚本与待办；勾选和添加待办；记录观看、在线、询盘及文字复盘 |
| 数据复盘 | 录入、编辑、删除视频累计数据；发布日筛选；播放、点赞和询盘统计及比率；原生 Canvas 折线 / 柱状图与数据明细表 |
| 个人中心 | IP 名称、定位和表达风格自动保存；深色 / 浅色主题；全部数据 JSON 导出、校验与覆盖恢复 |

概览实时显示灵感、选题、文案和直播数量。保存文案时，关联的“待写”选题会进入“制作”；录入关联视频的数据后会进入“已发布”。删除来源灵感或选题不会级联删除已生成的内容。

## 本地生成的能力边界

- **不抓取抖音链接**：链接只作为来源记录，分析依赖你粘贴的文案，不访问平台。
- **不调用 AI**：分析使用关键词与文本结构规则；选题和口播采用本地模板，直播采用可编辑的流程模板。分析不是流量预测，生成结果需自行核对事实和专业信息。
- 口播按约 **3.5 字 / 秒（不计空白）**估算目标篇幅，页面展示实际字数和估算时长；真实语速、停顿和演示会影响时长，请朗读确认。
- 本地文案生成参考 IP 定位、表达风格中的“简洁 / 直接 / 短句”“温柔 / 亲切 / 陪伴”等关键词，以及最近保存文案的平均句长。它属于简单规则适配，不能训练模型或理解全部个人风格。
- 每条视频保存一份**最新累计数据**，更新用“编辑”，不要重复添加。同一关联选题或同标题同发布日期的重复记录会被拦截。图表按**发布日期**聚合累计数据，不代表播放发生日的增长曲线。

## 开始使用

无需安装、构建或配置密钥。建议在仓库根目录运行：

```sh
python3 -m http.server 8000
```

通过浏览器访问该本地服务。也可以直接打开 `index.html`，但 `file://` 的存储行为因浏览器而异，推荐 HTTP 或 GitHub Pages。

建议操作顺序：

1. 在个人中心填写 IP 信息与表达风格。
2. 在爆款拆解中粘贴文案，生成并保存报告。
3. 在灵感库记录自己的素材，填写逗号分隔的标签。
4. 点击“一键衍生选题”得到五套候选，选用后进入文案生成。
5. 填写时长与真实素材，生成、编辑并保存文案版本。
6. 在直播中心准备策划、检查待办，直播后填写复盘。
7. 在数据复盘录入视频发布后的最新数据，对比内容表现。
8. 定期在个人中心导出完整 JSON 备份。

手机端导航可左右滑动；页面支持键盘操作、焦点提示、跳过导航链接与操作结果播报。已录入的表单草稿会保留到下次打开，明确点击清空、新建或切换版本可能替换对应草稿。

## 数据与备份

- 数据键：`gongzuo.workspace.v1`，沿用首版设置，自动兼容早期仅包含个人信息的本地数据。
- 数据只属于当前浏览器、当前来源。设备、浏览器、域名、协议或端口改变后，不会自动迁移；清除网站数据也会删除记录。
- 导出包括设置、报告、灵感、选题、全部文案版本、直播脚本 / 待办 / 复盘、视频数据和草稿。
- 导入支持本站导出的版本 1 JSON；先验证结构、ID、状态、日期和数值，再询问是否覆盖。格式错误、取消恢复或存储写入失败时，原数据保留。最大导入文件 20 MB。
- 存储空间不足时不会提示保存成功；请先备份，再清理不需要的数据。遇到损坏的本地 JSON 时会暂停写入，并允许在个人中心导出原始存储或导入有效备份。
- 本地存储没有账户隔离或加密，请不要填入密码、令牌、客户隐私等敏感信息。备份文件也应妥善保管。

## GitHub Pages 部署

1. 确保全部文件已推送到 `guantanxx/Gongzuo` 的 `main` 分支，入口 `index.html` 在根目录。
2. 打开仓库 **Settings → Pages**。
3. 在 **Build and deployment** 选择 **Deploy from a branch**。
4. 选择 **main** 和 **/ (root)**，点击 **Save**。
5. 等部署成功后，访问 Pages 面板提供的网址，通常是 `https://guantanxx.github.io/Gongzuo/`。

全部资源使用相对路径，适配仓库子路径。无需构建步骤或环境变量；后续推送到 `main` 会由 GitHub Pages 更新部署（启用上述设置后）。
